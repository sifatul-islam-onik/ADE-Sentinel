# ADE-Sentinel — CPU runtime for the demo. REQUIRED, despite the file name.
#
# These were originally "dev extras": optional packages so that tests for
# remote-only code could execute on the machine that wrote it, and so the
# inference-only analysis steps could run Kaggle's checkpoints on CPU.
#
# After the repo was trimmed to the demo, they are no longer optional.
# app/streamlit_app.py loads real checkpoints on CPU at startup, so
# requirements-local.txt alone will not start the app. Install both:
#
#   .venv\Scripts\python -m pip install -r requirements-local.txt
#   .venv\Scripts\python -m pip install -r requirements-dev.txt \
#       --extra-index-url https://download.pytorch.org/whl/cpu
#
# CPU wheels only — no CUDA. Training happened on Kaggle and is not reproducible
# from this tree without restoring scripts/ (see README, "Repository scope").
#
# Historical note, kept because it explains why the test suite mattered:
# PLAN F7 kept torch off the local environment because every neural run executed
# on Kaggle. A side effect was that tests/test_stage1_models.py,
# tests/test_bilstm_tagger.py and the CRF tests skipped locally — so a bug in
# them was only discovered inside a Kaggle session, after the clone, the install
# and the GPU allocation. That cost two sessions during Phase 5, on two real
# defects:
#
#   1. A test built one model with the default dropout and the other with 0.0,
#      then asserted their configs were identical.
#   2. A test asserted an untrained CRF cannot emit an illegal tag transition.
#      It can — pytorch-crf initialises its transition matrix uniformly and
#      forbids nothing. The clean output in run 10 is LEARNED, not structural.

torch                 # CPU build; see the --extra-index-url above
pytorch-crf==0.7.2    # run 10's BiLSTM-CRF tagger — the demo's DEFAULT Stage 2
transformers==5.0.0   # the version run 11 trained with (its saved config.json)
streamlit==1.63.0     # the demo itself, app/streamlit_app.py
