# ADE-Sentinel — DEV extras for the local machine. Optional.
#
# Nothing in the training pipeline needs these locally. They exist so the tests
# for remote-only code can execute on the machine that writes it - and, since
# Phase 5, so the inference-only analysis steps (5.9 and all of Phase 6) can run
# the checkpoints Kaggle produced on CPU. scripts/check_stage2_inference.py
# verifies that CPU decode matches the remote decode before those are trusted.
#
# The problem they solve: PLAN F7 keeps torch off the local environment because
# every neural run executes on Kaggle. A side effect is that
# tests/test_stage1_models.py, tests/test_bilstm_tagger.py and the CRF tests
# skip locally — so a bug in them is only discovered inside a Kaggle session,
# after the clone, the install and the GPU allocation. That cost two sessions
# during Phase 5, on two real defects:
#
#   1. A test built one model with the default dropout and the other with 0.0,
#      then asserted their configs were identical.
#   2. A test asserted an untrained CRF cannot emit an illegal tag transition.
#      It can — pytorch-crf initialises its transition matrix uniformly and
#      forbids nothing. The clean output in run 10 is LEARNED, not structural.
#
# Both are caught in about three seconds locally with these installed.
#
# Install (CPU wheels only — no CUDA):
#   .venv\Scripts\python -m pip install -r requirements-dev.txt \
#       --extra-index-url https://download.pytorch.org/whl/cpu
#
# This does NOT change where the real runs happen. The CPU build is for the
# tiny synthetic tensors in the test suite; training still belongs on Kaggle.

torch          # CPU build; see the --extra-index-url above
pytorch-crf==0.7.2
transformers==5.0.0   # the version run 11 trained with (its saved config.json)
streamlit==1.63.0     # Phase 7 demo, app/streamlit_app.py; also its test in tests/
